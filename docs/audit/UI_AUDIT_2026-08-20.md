# Teacher Studio UI Audit — 2026-08-20

Triggered by: the unit "..." (kebab) menu on the Curriculum page being clipped, making
"Move to Trash" unreachable. Fixed the same day; this document records the fix, the
quick wins shipped with it, and the deferred findings from the broader teacher-UI sweep.

Scope: teacher entry only (`apps/teacher/*`, `components/shared/*`). No backend,
migration, or edge-function changes.

---

## 1. Fixed in this pass

### 1.1 The reported bug — kebab dropdown clipped by the card's `overflow-hidden`

**Root cause.** In `apps/teacher/UnitList.tsx`, the unit card wrapper
(`motion.div`, was line 280) had `overflow-hidden` — there only to clip the
thumbnail's rounded corners. The kebab dropdown (`absolute right-0 top-8 z-20`)
rendered *inside* that card, so everything past the card's bottom border was cut
off. `z-20` cannot help against an overflow clip — it's geometry, not stacking.
The delete flow itself was fully functional (confirm modal + `handleTrashUnit`
+ `trash_unit` RPC); only the menu item opening it was unreachable.

**Fix.**
- Unit card: removed `overflow-hidden` from the card wrapper; the thumbnail keeps
  its own `overflow-hidden` (for the hover zoom) and now carries `rounded-t-xl`.
- Book card: same wrapper treatment; the `h-40` header keeps clipping for the
  image but the kebab block moved out of the header to be a direct child of the
  card wrapper (`absolute top-3 right-3 z-20`), so the menu is no longer inside
  any clipping ancestor.
- Menu dismissal: replaced the two `fixed inset-0 z-10` overlay divs with one
  document-level `mousedown` + Escape `keydown` listener pair scoped to
  `menuOpenFor` (clicks inside `[data-kebab-menu]` are ignored). This also fixes
  a latent quirk: the card's `hover:-translate-y-1` transform made the
  `fixed` overlay card-relative while hovering, breaking outside-click dismiss.

### 1.2 Book trash had no confirmation

`handleTrashBook` soft-deleted a book directly from the kebab menu click, while
unit trash (right next to it) had a proper confirm modal. Added a `bookToTrash`
state + confirmation modal mirroring the unit one, with `isDeleting` pending
state and disabled buttons. Copy is accurate to the RPC (`trash_book` only marks
the book; its units survive and show under Unassigned until restore/reassign).

### 1.3 Double-submit on create buttons

- `ClassManagement.tsx` — `handleCreateClass` had no pending state; a double-click
  created two classes. Added `creatingClass` guard + spinner/"Creating…" on the
  modal's Create button.
- `Assignments.tsx` — same for `handleCreateAssignment`, using the react-query
  mutation's `isPending` (no new state needed).

### 1.4 Decorative search + level filter on the Curriculum bookshelf

The search input and level `<select>` had no `value`/`onChange` — pure decoration.
Now controlled: `searchQuery` filters books (by title or containing-unit title) and
unassigned units by title; `levelFilter` filters units with lenient matching
(`unit.level` is freeform — "A1" vs "Beginner (A1)" match in either direction);
level options are derived from levels actually present in the data.

### 1.5 Bookshelf empty state

With no books and no unassigned units, the page rendered blank under the filters.
Added a dashed-border empty state (distinct copy for "no books yet" vs "no matches
for your search/filters"), matching the existing trash/book-detail pattern.

### 1.6 A11y micro-pass (scoped)

- Kebab buttons: `aria-label` ("Actions for <title>"), `aria-haspopup="menu"`,
  `aria-expanded`; menus get `role="menu"`.
- `SharedUI.tsx` `Modal`: Escape now closes it; panel gets `role="dialog"`,
  `aria-modal`, `aria-label={title}`; close button gets `aria-label`.

**Verified:** `npx tsc --noEmit` → 0 errors in app code (only the usual pre-existing
Deno/edge-function noise under `supabase/`); `npm run build` (vite + PWA) passes.

## 2. Deferred findings (not fixed in this pass)

Line numbers below refer to the files as of 2026-08-20 *before* this pass's edits
(UnitList.tsx numbers have shifted since).

### 2.1 Dead / fake controls — user-visible lies (highest UX priority)

| Where | What |
|---|---|
| `Assignments.tsx:127-129, 142-147, 155-165, 93, 95-97` | Kebab button, "View Details", "Stats", "Create New Assignment" card, search and Filter — all have **no onClick**. The page is read-only except the Create modal. |
| `Reports.tsx:87-93` | Timeframe dropdown + "Export Report" — no handlers. |
| `DashboardHome.tsx:65, 97, 167` | "Good Morning" hardcoded regardless of time; "Up Next" is just `classes[0]`; "View All" dead. |

Recommendation: hide unimplemented controls rather than shipping them disabled-looking.
The mobile settings screens in particular present a facade of functionality.

### 2.2 Silent error-as-empty-state

- `MediaPickerModal.tsx:46-47` — supabase error → `setAssets([])` → renders
  "No assets available yet" (misleading).
- `ResourceLibrary.tsx:94-95` — identical pattern → "No media yet".
- `Reports.tsx:42-43` — catch logs only; page shows all-zero stats.
- `TeacherMessages.tsx:55-56, 68-69` — load errors log-only → empty inbox.
- `store/SessionContext.tsx:892-895` — `loadUnits` has no try/catch and is called
  fire-and-forget (`UnitList.tsx:96`) → on failure the Curriculum page is silently
  blank with an unhandled rejection.

Fix pattern: toast on catch + an explicit error state distinct from empty.

### 2.3 Data-integrity flag (belongs with the workstream-C fix plans)

`UnitContentVault.tsx:243-245, 277-279, 310-312` — the canonical relational writes
(vocabulary_items / grammar_rules / story_pages delete-then-insert) fail with
`console.warn` only, while the user sees the manifest-save success toast. Silent
data divergence. Also `:141` uses `window.confirm` before an AI regeneration that
bulk-deletes rows — deserves a real modal with irreversible-action copy.

### 2.4 Consistency / robustness

- **Modal proliferation:** at least 5 hand-rolled modal variants (SharedUI `Modal`,
  8 inline modals in UnitList, bottom-sheet pair, `z-[120]` attendance pair,
  `z-[80]` MediaPicker, full-screen UnitStudio review). Consolidate on
  `SharedUI` Modal (now Escape-capable) or extract its overlay as a base.
- **No z-index scale** in `tailwind.config.js`; usage spans z-10…z-[200] with
  arbitrary values (`z-[80]`, `z-[100]`, `z-[120]`, `z-[200]`). Define a scale.
- **Pending-state gaps:** restore/move/reorder buttons in UnitList trash view
  (`:538, 541, 560, 563`) have no disabled/pending — double-click double-fires.
  `handlePlan` (`:169-176`) uses one shared `isLoading`, so every card's Plan
  button spins at once, plus a gratuitous 500 ms `setTimeout`.
- **Native `confirm()` ×3:** `ClassManagement.tsx:391` (roster remove — also no
  pending state), `Passports.tsx:74`, `UnitContentVault.tsx:141`. Replace with a
  shared ConfirmDialog once modals are consolidated.
- **Dead code:** `UnitPreviewModal` is rendered (`UnitList.tsx:635-642`) but can
  never open (`setSelectedUnit` only ever receives `null`) and shows fabricated
  demo data; `StudentSelectorModal.tsx` is imported nowhere; the "Generate
  Lesson" button opens a deprecated detour modal (`UnitList.tsx:644-661`) that
  just redirects to the upload workspace.

### 2.5 Accessibility (broader than the micro-pass)

- Zero `aria-label`s across `apps/teacher` outside this pass's fixes. Icon-only
  unlabeled buttons: modal close Xs (Attendance/MediaPicker/CharacterPicker),
  trash buttons in UnitContentVault/StudentPathComposer, LiveCommander
  pen/eraser/nav, TeacherMessages back, DashboardHome FAB, mobile hamburger.
- No keyboard navigation on menus (arrows/roving focus); Escape only where added
  in this pass.
- No focus trap or focus restoration in any modal; `SharedUI.tsx:36-41` `Field`
  label lacks `htmlFor`/id association.

### 2.6 Tech-debt note

The kebab dropdown remains absolutely positioned (no portal). It now escapes all
clipping ancestors, but a portal/floating-positioned shared Dropdown component
(there is none in the codebase) would be the durable pattern if menus grow
(smarter flip-up near viewport bottom, submenus, etc.).
